SPEC draft 0.5 — the built-in font, in the core and on the Pico 2
=================================================================

**Status:** the core, on 2026-09-16. Every check below passed. `VDP-PLAN.md`
(local) section 5, steps 4 and 5.

**The headline.**

- **The core implements draft 0.5.** Reset writes font `$00` to `$0800`–`$0FFF`
  after the palette, at power-on and on every `RST`. Register `$30` `FONT` records
  a load for layer 0's or layer 1's pattern table, its base sampled at the write,
  and carries it out at the line start where vertical blank fires, before `F`
  sets. `STAT6` reads `$BF`.
- **The oracle holds five fixtures and eighteen checkpoints**, re-synced from
  6502-EMULATOR `527b53c`. `vdp-font` never calls `KernalInit`, so nothing but the
  card's own font can reproduce it, and it replays exactly through both host paths.
- **All 364 tests of `Video.test.ts` pass against the core**, the 21 font tests
  among them, and `STAT5 $05` / `STAT6 $BF`.
- **`Video.ts` and the core agree under fuzzing with `FONT` in the stream**:
  10⁷ operations in the tiles scope and 8 × 10⁶ in the frames scope, no
  divergence. A planted bug in layer 1's load diverges at operation 28,010.
- **No font byte is typed into C.** `core/CMakeLists.txt` turns
  `fonts/cp437-6x8.bin` into `font_data.c` in the build tree, for the host and
  the RP2350 alike, and `test_font` checks the result against the file.

Bulk writes
-----------

The plan's `vdp_bulk_write` marked each 1 KB page it touched, for the catch-up to
copy whole. That is how a full journal is handled, and it has the flaw
`test_latch` names: a page is copied from the bus side *as it is at the
catch-up*, so a render side that is late sees writes made after its latch. For a
journal overflow no 6502 can cause that is acceptable. A font load happens every
time a program asks for one, and `RST` is ordinary, so here it would not be.

So a bulk write is journaled as one entry instead: a pointer to constant data
(the font, or the card's copy of the reset palette), its address and length, and
the journal tail it found. The bus copy takes the bytes at once. The catch-up
replays the byte journal and copies each bulk entry when the replay reaches its
place, then refreshes the palette cache entries it covered. A late catch-up
takes exactly what a prompt one does, which `test_latch`'s random late-catch-up
comparison now shows with loads and resets in its stream.

The ring holds 16. One that finds it full marks its pages, as a full journal
does, without counting a journal overflow; that needs eight resets, or eight
frames' loads for both layers, before the render side takes one latch.

The copy is in the latch interrupt only on the bus side: two `memcpy`s of
2,048 bytes at most. The render side's copies run in the renderer's thread.

Differences from the plan
-------------------------

- **Bulk writes are journaled, not page-marked** (above). The plan's
  "sets `dirty_pages` for every page touched" survives only as the fallback for a
  full bulk ring.
- **A debugger's write to `FONT` loads.** `VDP-PLAN.md` step 3 said a debugger's
  `setRegister` should not; `Video.ts` at `527b53c` does, and the core follows the
  reference (`test_font`'s `a_debuggers_write`).
- **`vdp-font`'s checkpoints are `reset`, `loaded` and `relocated`**, the
  emulator's names, not the plan's `reset`, `load-l0` and `load-l1`.
- **`textGrid` in the adapter** applies the scroll, which the re-sync required:
  `replay_vdp-layers` failed on `textGrid` until it did.

Reproducing
-----------

```sh
export PICOVDP_EMULATOR=<a clean 6502-EMULATOR checkout on v3-vdp, after npm ci && npm run build:cli>
node tools/sync-oracle.mjs --check
node tools/replay.mjs --reference
cmake --workflow --preset host        # 26 tests
cmake --workflow --preset host-asan   # 20
node tools/replay.mjs --classes
build/host/host/replay/vdp-replay --classes tests/oracle/*/*.vdpt.gz
node tools/fuzz.mjs --scope tiles --seed 1 --ops 10000000
node --max-old-space-size=8192 tools/fuzz.mjs --scope frames --seed 1 --ops 8000000

# in the emulator checkout
PICOVDP_ADDON=$HOME/Developer/C/6502-PICOVDP/host/node/Video.cjs npm run test:picovdp
```
